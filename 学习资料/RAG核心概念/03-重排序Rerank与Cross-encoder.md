# 概念三：重排序（Rerank）与 Cross-encoder

## 一、为什么需要重排序

混合召回阶段相当于"海选"：
- 从大量文档（几万~几十万段）里快速筛出候选（如 50 段）
- 这一步追求"快"和"别漏掉"，允许混进不那么相关的

重排序阶段相当于"面试精选"：
- 候选数量少了，可以用更精细的标准重新评估
- 重新打分排序，挑出最相关的前 3~5 个
- 这一步追求"准"

## 二、两阶段检索

```
海量文档（几万~几百万段）
       ↓
第一阶段：召回（Retrieval）—— 快速、粗糙，筛出候选集（如 top 50）
       ↓
第二阶段：重排序（Rerank）—— 慢速、精细，从候选里挑最相关的（如 top 5）
       ↓
   送给大模型生成答案
```

### 为什么不直接在第一阶段算准

速度和精度的矛盾：
- 第一阶段要从海量文档里找，必须快
- 精度高的计算方式很慢，全库使用无法接受
- 所以先快筛，把数量降到几十，再精排

## 三、Bi-encoder（双塔模型）—— 召回阶段

```
问题 → 编码器 → 问题向量
文档 → 编码器 → 文档向量
                    ↓
            算两个向量的余弦相似度
```

- 问题和文档分别独立走"塔"，编码时互相看不到
- 文档向量可以提前算好存起来，提问时只算问题向量
- 优点：非常快，适合全库检索
- 缺点：精度有限，可能错过深层匹配

## 四、Cross-encoder（交叉编码器）—— 重排序阶段

```
把问题和候选文档"拼在一起"，同时输入模型
        ↓
问题的每个词 和 文档的每个词 通过注意力机制互相"看到"
        ↓
模型直接输出相关性分数
```

- 问题和文档在编码时充分交互，每个词都能看到对方
- 能捕捉细微的匹配关系（如"粗车"vs"精车"）
- 优点：精度非常高
- 缺点：非常慢，每个"问题-文档"对都要单独跑一次，不能提前算
- 只能用于已经筛出来的少量候选

### 对比

| 对比 | Bi-encoder（双塔） | Cross-encoder（交叉） |
|---|---|---|
| 问题和文档 | 分别独立编码，互相看不到 | 拼在一起，词与词充分交互 |
| 文档向量 | 可以提前算好存起来 | 不能提前算，必须和问题一起输入 |
| 速度 | 很快，适合全库检索 | 很慢，只能处理少量候选 |
| 精度 | 一般 | 很高 |
| 用在哪个阶段 | 召回（第一阶段） | 重排序（第二阶段） |

## 五、RRF（倒数排名融合）

混合召回的两路结果（向量、BM25）的一种融合方法。

### 为什么不能直接加分数
- 向量分数是相似度（0~1）
- BM25 分数是另一套尺度
- 两路分数含金量不同，直接相加会乱

### RRF 思路
只看排名，不看具体分数：
- 文档在每路结果里排名越靠前，得分越高
- 公式：score(d) = Σ 1/(k + rank_i(d))，k 通常取 60
- 只在一路出现的文档也有分

优点：简单、鲁棒，不用管分数尺度差异，工业界常用。

### RRF 和 Cross-encoder 的位置

```
向量召回 top50 ──┐
                 ├─→ RRF 融合（合并两路候选）→ 候选集
 BM25召回 top50 ──┘                              ↓
                                         Cross-encoder 精排
                                                 ↓
                                         最终 top 5 给大模型
```

- RRF 解决"两路结果怎么合并"
- Cross-encoder 解决"怎么给候选精细打分"

## 六、完整检索流程

```
用户提问
   ↓
【召回阶段】（快、全）
   ├─ 向量检索（Bi-encoder）→ top 50
   └─ BM25 关键词检索 → top 50
   ↓
RRF 融合 → 合并去重，得到候选集
   ↓
【重排序阶段】（慢、准）
   Cross-encoder 对每个候选精细打分
   ↓
取 top 3~5 段最相关的文档
   ↓
拼进 Prompt，交给大模型生成答案
```

## 七、为什么是企业级的

1. 召回阶段用混合方式：保证该找的都能找到，不漏
2. 重排序用 Cross-encoder：保证送给大模型的是真正最相关的内容
3. 垃圾进垃圾出：检索内容不对，大模型再强也生成不出正确答案

对应项目要求：
- 第（2）条：稠密+稀疏混合召回
- 第（3）条：重排序模块
