# 概念一：Embedding（向量嵌入）

## 大白话解释

**Embedding 就是把一段文字变成一串数字，让计算机能"理解"文字的意思。**

你可以把它想象成给每段文字发一张"**语义坐标卡**"：

- 意思相近的文字，坐标也相近
- 意思不相关的文字，坐标离得远
- 这串数字就是"向量"（Vector）

## 直观例子

假设我们用一种简单的方式给词打分（实际维度更多，比如 768 维、1536 维）：

| 词语 | 维度1（机械相关度） | 维度2（动作相关度） | 维度3（材料相关度） |
|---|---|---|---|
| 车削 | 0.9 | 0.8 | 0.3 |
| 铣削 | 0.9 | 0.7 | 0.3 |
| 车床 | 0.9 | 0.1 | 0.2 |
| 炒菜 | 0.0 | 0.7 | 0.1 |
| 45号钢 | 0.8 | 0.0 | 0.9 |

可以看到：
- "车削"和"铣削"的数字很像 → 它们都是机械加工方法
- "车削"和"炒菜"数字差很远 → 意思完全不相关
- 计算机不需要"懂"中文，只看数字距离就知道语义相不相似

## 实际的向量长什么样

真实的 Embedding 向量（以 OpenAI 的 text-embedding-3-small 为例，1536 维）：

```
"45号钢车削参数"
→ [0.0213, -0.0872, 0.1543, ..., 0.0098, -0.0321]  （一共1536个数字）
```

每一维代表什么，人很难直接解释，但整体上它编码了这段文字的语义信息。

## 怎么判断两段文字像不像

用**余弦相似度**（Cosine Similarity）计算两个向量的夹角：

- 相似度 = 1：意思几乎一样
- 相似度 = 0：完全不相关
- 相似度越接近 1，语义越接近

## 核心概念

### 稠密向量（Dense Vector）
每一维都有数值，大部分数字不为0，用一长串数字整体表达语义。

### Embedding 模型
专门用来把文字转成向量的模型，比如 OpenAI Embedding、BGE、M3E 等，不需要自己训练，直接调用。

### 相似度计算
计算两个向量的距离/夹角，判断语义是否相似。

## 为什么是 RAG 的基础

RAG 的检索逻辑是：

```
用户问题 → 转成向量 → 去数据库里找向量距离最近的文档段落
```

如果没有 Embedding，计算机只能做关键词匹配（必须出现一模一样的词）；有了 Embedding，即使字面不同但意思相近，也能找到。

例如：
- 用户问："45号钢怎么车？"
- 文档里写的是："45钢粗车切削参数推荐"
- 没有完全匹配的字，但 Embedding 能理解它们语义相关

## 关键要点

1. Embedding 是一个"翻译官"：把文字翻译成计算机能比较的数字向量
2. 语义相近 = 向量距离近：这是向量检索的基础
3. Embedding 模型是预先训练好的：不需要自己训练，直接调用
4. 文档和问题用同一个模型转：才能在同一个空间里比较
