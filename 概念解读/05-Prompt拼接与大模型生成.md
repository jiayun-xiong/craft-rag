# 概念五：Prompt 拼接与大模型生成

## 一、什么是 Prompt 拼接

大模型本身是"闭卷"的，不知道用户的私有文档。
RAG 把检索到的资料和用户问题一起打包成提示词发给大模型，让它"照着书回答"，这就是开卷考试的核心动作。

## 二、RAG Prompt 的三部分结构

```
① 系统提示（System Prompt）：角色、规则、输出格式
② 检索到的资料（Context）：重排序后的 top 3~5 段文档
③ 用户问题（Question）：用户实际问题
```

工艺生成项目示例：
```
【系统提示】
你是一个机械加工工艺专家。请严格根据下面提供的参考资料，
生成零件的加工指令。要求：
1. 只能依据参考资料回答，不得编造参数；
2. 资料不足时回答"资料不足，无法确定"；
3. 每条参数后用 [编号] 标注来源；
4. 按工序、刀具、切削参数的格式输出。

【参考资料】
[1] 45号钢粗车：切削速度100~120 m/min……
[2] 45号钢精车：切削速度150~180 m/min……

【用户问题】
请给出 45号钢轴类零件的车削加工指令。
```

## 三、系统规则的作用

1. **只能依据资料回答**：RAG的灵魂，约束模型不编造，防止幻觉
2. **资料不足就说不知道**："查不到"是安全的，"给错参数"会出事故
3. **标注引用编号**：实现引用溯源，对应项目要求第（4）条
4. **规定输出格式**：输出加工指令而不是随便的回答

## 四、结构化输出

让模型输出 JSON，方便程序解析和前端展示：

```json
{
  "零件": "45号钢轴类零件",
  "工序": [
    {"序号":1,"工序名称":"粗车","刀具":"硬质合金车刀",
     "切削速度":"100~120 m/min","进给量":"0.15~0.30 mm/r",
     "背吃刀量":"2~4 mm","引用":[1]}
  ]
}
```

好处：
- 可渲染成工序卡片、表格
- 可对接生产系统
- 结果稳定可解析
- 体现"生成加工指令"而非"回答问题"

可在 Prompt 里给 JSON 示例（Few-shot）引导格式。

## 五、资料不是越多越好

### 1. 上下文窗口有限
大模型一次能接收的 token 数有上限。

### 2. 迷失在中间（Lost in the Middle）
模型对开头和结尾内容记得最清楚，中间内容易忽略：
- 最相关资料放前面或最后
- 只塞 top 3~5，不要塞无关资料

### 3. 垃圾进，垃圾出
检索资料不对，再强的模型和 Prompt 也没用。

### 4. 检索质量 ≫ 模型大小
把检索做准，比换更大模型更重要。技术难点在检索链路，不在调用大模型。

## 六、流程位置

```
用户提问
  ↓
混合召回 + 重排序 → top 3~5 段精准资料
  ↓
Prompt 拼接（系统提示 + 检索资料 + 用户问题）
  ↓
调用大模型 API
  ↓
生成结构化加工指令 + 引用编号
  ↓
返回用户，可点击溯源
```

## 七、可选大模型

- OpenAI GPT-4o-mini：能力强、便宜、有 JSON 模式
- Claude Haiku：速度快、性价比高
- 国内文心/通义 API：国内访问稳定、中文好

调用大模型只是一个简单 API，难点在前面的检索链路。
