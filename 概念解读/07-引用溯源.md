# 概念七：引用溯源（Citation / Source Attribution）

## 一、为什么是企业级刚需

大模型输出的是要拿去操作机床的加工参数，工程师必须能回答：
"这个数字从哪来的？"

- 无法验证 → 不敢用，万一是幻觉
- 能一键点回手册第142页 → 才敢采纳

引用溯源的本质：让 AI 输出可验证、可追溯、可担责。

## 二、实现原理

### 第一步：入库时每个块带"身份证"（元数据）
```json
{
  "chunk_id": "doc_003_p142",
  "content": "45号钢粗车切削速度100~120 m/min……",
  "metadata": {
    "source": "机械加工工艺手册.pdf",
    "page": 142,
    "section": "4.2 车削用量"
  }
}
```

### 第二步：检索返回块+元数据
重排序返回的每个块都带来源信息。

### 第三步：Prompt 给资料编号，模型标注引用
```
粗车切削速度100~120 m/min [1]……
参考来源：
[1] 机械加工工艺手册.pdf 第142页 §4.2
```

### 第四步：前端渲染为可点击链接
- 点击 [1] → 打开PDF翻到第142页
- 可高亮原文片段、悬停预览

## 三、溯源粒度

| 粒度 | 定位到 | 难度 |
|---|---|---|
| 文档级 | 哪份PDF | 最简单 |
| 页码级 | 哪份文档第几页 | 中等（解析时保留页码） |
| 段落级 | 哪段，高亮原文 | 较精细 |

项目做到页码级就很完整，段落级是加分项。关键是PDF解析时保留页码信息。

## 四、模型会乱标引用，必须警惕

1. **无中生有**：标了[1]但内容和资料[1]无关
2. **张冠李戴**：内容来自[2]却标成[1]
3. **该标不标**：用了资料却没标
4. **编造来源**：生成不存在的[5]

应对：
- 强约束 Prompt：每个参数必须标注，没有就声明
- 结构化输出：JSON 中每条参数强制绑定引用编号
- 后处理校验：检查编号是否在合法范围内
- 只给检索到的资料：模型只能引用喂给它的几段

## 五、依赖整条链路

```
PDF解析：记住页码
  → 分块：每个块带 metadata
  → 检索：返回块带元数据
  → Prompt：给资料编号要求引用
  → 生成：带编号的结构化答案
  → 校验：编号合法性
  → 前端：点击跳转到原文并高亮
```

## 六、企业级意义

- 输出可核对，人工确认后才采用
- 出问题可追溯到依据
- 参数错了可能导致安全事故，"可验证"比"流畅"更重要

对应项目要求第（4）条：引用溯源。

## 七、完整 RAG 链路总图

```
【离线建库】（一次）
  工艺PDF → ①解析 → ④分块（带元数据）→ Embedding向量化
  → 存入向量库（稠密）+ BM25索引（稀疏）

【在线问答】（每次提问）
  用户问题
  → ⑥多轮对话：查询改写
  → ②混合召回：向量 + BM25
  → ③RRF融合 + Cross-encoder重排序
  → ⑤Prompt拼接
  → 大模型生成结构化加工指令
  → ⑦引用溯源
```
