# 概念二：稠密检索（向量检索）与稀疏检索（BM25）

## 一、向量检索（稠密检索）的工作原理

```
1. 文档库的每一段，都已经提前转成了向量
2. 用户的问题，也用同一个 Embedding 模型转成向量
3. 计算问题向量和所有文档向量的相似度
4. 取相似度最高的 top-k 段（比如前10段）
```

叫"稠密检索"是因为用的是稠密向量，每一维都有值。

## 二、稠密检索的优点

1. **懂语义、懂同义词**：
   - 问题："怎么把金属切光滑一点？"
   - 能找到"提高表面粗糙度的方法"
   - 即使没有一个字完全重复，意思对就行

2. **能理解上下文**：
   - "它"指代什么、"这个参数"是什么意思
   - 向量能捕捉整体语义

3. **跨语言、跨表述**：
   - 中英文之间、不同说法之间，语义相近就能匹配

## 三、稠密检索的致命缺点

**向量检索对"精确的关键词、专有名词、数字、型号"非常不敏感。**

| 问题 | 向量检索可能出的错 |
|---|---|
| "45号钢的切削参数" | 可能找到"40Cr钢"、"20号钢"，因为它们都是"钢的切削参数"，语义很像 |
| "YT15刀具适合什么材料" | 可能找到"YT5"、"YG8"，都是刀具型号，向量上差别很小 |
| "进给量 0.15 mm/r" | 0.15 和 0.2、0.1 在向量空间里几乎没区别 |
| "GB/T 12204 标准" | 标准号差一个数字，向量上可能完全分不出来 |
| "直径 50mm 的轴" | 40mm、60mm 都可能被召回，数字对它来说就是"差不多" |

**根本原因：**
Embedding 模型在训练时重点是学习"语义"，会把"差不多的东西"压缩到相近的位置。但机械加工里，型号、数字、标准号差一个字符，结果可能完全不同，不能"差不多"。

另外，向量检索会"脑补"：问题里提到的东西如果文档里没有，它会找一个"看起来像"的塞给你，而不是告诉你"没有"。这在企业级场景里很危险。

## 四、BM25（稀疏检索/关键词检索）

BM25 是一种关键词匹配算法，是传统搜索引擎用的核心算法。

### 工作逻辑
- 问题里出现了什么词，就去找包含这些词的文档
- 词越稀有、出现次数越合适，匹配分越高
- 没有这个词，就是不匹配，不会"脑补"

### 为什么叫"稀疏检索"
它的向量表示是"稀疏"的：
- 词表里有几十万个词
- 一段话里只出现十几个词
- 这十几个词的位置有值，其他位置全是 0

## 五、BM25 的优点

1. **精确匹配能力强**：
   - 找"45号钢"，就是找包含"45号钢"这四个字的段落
   - 不会给你换成"40Cr"

2. **对型号、数字、专有名词很敏感**：
   - YT15 就是 YT15，不会匹配 YT5
   - GB/T 12204 就是这个标准号

3. **不会无中生有**：
   - 没有这个关键词，就不返回，不会硬塞一个像的

## 六、BM25 的缺点

1. **不懂同义词**：
   - 搜"表面光整度"，找不到写"表面粗糙度"的文档
   - 必须字面上一模一样

2. **不懂语义**：
   - "怎么让零件更光滑" → 关键词匹配不到"提高表面质量"
   - 一个是"光滑"，一个是"表面质量"，字面上没重叠

3. **对表述方式要求高**：
   - 换个说法就找不到了

## 七、稠密检索 vs 稀疏检索 对比

| 对比维度 | 稠密检索（向量） | 稀疏检索（BM25） |
|---|---|---|
| 匹配方式 | 语义相似 | 关键词精确匹配 |
| 同义词 | 支持 | 不支持 |
| 数字/型号 | 非常弱，容易混 | 非常强，精确匹配 |
| 专有名词 | 容易混淆相近的 | 精确，不会错 |
| 没结果时 | 会硬塞一个像的 | 不返回，不会脑补 |
| 语义理解 | 强 | 弱 |
| 典型场景 | 自然语言提问、模糊查询 | 精确查找、型号数字 |

## 八、为什么需要混合召回

两种检索的优缺点正好互补：

```
用户提问
   ├── 稠密检索（向量）→ 找语义相关的，保证"不遗漏"
   ├── 稀疏检索（BM25）→ 找关键词精确匹配的，保证"不出错"
   └── 两路结果合并 → 既懂意思，又能精确匹配
```

- 纯向量：可能找错型号、搞错数字
- 纯 BM25：换个说法就找不到
- 混合：两种情况都覆盖，这是企业级的做法
