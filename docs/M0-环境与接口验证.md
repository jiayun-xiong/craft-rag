# M0 环境与接口验证

验证日期：2026-11-21。主工作目录为本仓库根目录，代码后续放在根目录 src/。

## 为什么先做这一步

先独立验证模型服务，后续 PDF 解析、检索或回答出错时，才能区分是数据链路问题还是模型接入问题。本阶段不引入向量数据库和界面依赖。

## 复现

需要 Python 3.12。在仓库根目录执行：

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
# 仅在 .env 不存在时，从 .env.example 复制并填写密钥；不要覆盖已有配置。
.venv/bin/python scripts/check_api.py --offline
.venv/bin/python scripts/check_api.py
```

脚本始终从仓库根目录读取 .env，系统环境变量优先。真实密钥不得写入 .env.example；.env 已被 Git 忽略。联网检查会消耗少量 API 额度，发送的仅是脚本中的合成测试文本，不包含项目文档。

## 故障定位

- 配置失败：按脚本列出的变量名检查 .env，不能保留模板占位符。
- HTTP 401/403：检查密钥、权限和账户状态。
- HTTP 404/400：检查接口地址、模型名称及请求参数。
- HTTP 429：检查额度与限流。
- 连接或超时异常：检查网络、代理及服务状态。
- 响应验证失败：检查服务返回结构和模型配置。

为避免泄露密钥，脚本不打印响应正文、异常详情或请求头。每个请求超时 30 秒，无自动重试，失败仍继续检查其他接口，最终以非零退出码表示失败。
