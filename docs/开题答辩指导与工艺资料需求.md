# 开题答辩指导与工艺资料需求

整理日期：2026-11-21。指导意见来自项目负责人对开题答辩的转述。

## 老师的三条指导

1. 输入可能为 CAD 图。
2. 输出直接到机床。
3. 看一下目前开源的领域 RAG。

## 对项目的影响（供团队讨论）

根据项目负责人进一步说明，第 2 条的含义已明确：针对用户指定的零件，系统检索工艺资料，给出原材料、刀具、机床和加工工序，并生成可在所选机床及其控制器上执行、用于加工该零件的数控程序（NC 程序）。这项指导描述的是程序交付能力。自动传输程序、远程启动机床属于另外的集成功能，本次说明未要求。课程原题的五项验收要求继续保留。

实施建议：针对一个有完整图纸与工艺依据的零件，选定一种机床和控制器配置。将加工特征、装夹与工件零点、刀具编号与补偿约定、工序顺序及参数组织成结构化工艺方案，再由适配该控制器的编程模块生成 NC 文件。关键输入缺失时列出待确认项。验收记录分别说明控制器语法检查、按案例配置进行的刀路与几何仿真，以及是否完成实机验证。当前待确定的是样件、CAD 输入格式、目标设备和实际可用的验证条件。

当前基线通过 API 使用现成模型。“准备训练资料”的实际工作是收集可检索的工艺依据、准备每次生成所用的零件输入，并建立独立的人工评估集。可以先以一个阶梯轴为候选，把同图号、同修订版的一套资料配齐。

| 用途 | 优先收集的资料 | 用它回答什么 |
|---|---|---|
| 当前任务输入 | 零件 CAD 源文件、同版带标注工程图 PDF、材料与毛坯说明。注明图号、版本、单位。若用 STEP 模型，逐项核实尺寸公差、粗糙度和技术要求是否随模型提供 | 本次要加工哪些特征，各项要求来自哪个视图、尺寸标注或技术条款？ |
| 工艺知识库 | 同类零件已审核的工艺路线卡、工序卡、装夹示意图和检验规程；收集工序顺序及其适用条件 | 为什么先做这道工序，如何定位，如何判断加工结果符合要求？ |
| 工艺知识库 | 与案例实际材料、刀具型号匹配的厂商手册，以及车间的设备能力表、刀具和夹具清单 | 手册推荐的参数在什么条件下成立，该车间是否具备这些条件？引用应指到具体表格、行和单位 |
| 机床输出验证 | 目标机床与控制器型号、软件版本、编程和程序导入手册、后处理配置、对应装夹与刀具表，以及同一零件经审核的 NC 程序和仿真记录 | 输出文件能否被指定控制器读取？使用对应机床配置时，轨迹、坐标、刀具和行程是否符合该任务？真实设备下发和试切需要现场条件另行验证 |
| 人工评估 | 另留零件任务及参考工序卡，逐项标注允许的工艺方案、参数范围、适用条件、证据页和应追问的信息 | 检索是否命中正确依据，生成是否满足图纸要求，资料不足时是否识别缺口？ |

资料以图号和修订版关联，机床相关文件再关联机型与控制器版本。用于验收的同一零件标准答案、参考程序和评分标注单独保存，避免系统原样检索到答案。公开教学案例可以验证流程；使用模拟车间清单时应标记来源。机床仿真与人工工艺评分分别记录。

## 开源领域 RAG 初查

MedRAG 是医学领域的开源检索生成工具。值得借鉴的是固定评测任务、比较知识源和检索配置的做法。对应到本项目，可固定零件任务和生成模型，分别运行纯向量、混合召回、混合加重排，逐题检查证据页与工艺字段。代码仓库和论文属于调研资料，单独归档。[MedRAG 官方仓库](https://github.com/gzxiong/MedRAG)

RAGFlow 可作为通用文档 RAG 的工程对照，重点比较同一张参数表的解析效果。机床端则应查目标控制器自己的编程资料，例如采用 LinuxCNC 做仿真时可查其 G-code 文档。以上为初查，制造领域实现与本项目数据上的效果仍待评测。[RAGFlow 官方仓库](https://github.com/infiniflow/ragflow) · [LinuxCNC 官方文档](https://linuxcnc.org/docs/stable/html/gcode/overview.html)

## 第一批资料从哪里找

优先核查传动轴教学案例是否给出了可配对的零件图、工序及设备条件，再按案例所用材料和刀具补充手册。已有三菱 B196C 可先用于钢车削表格解析。独立 CAD 源文件和与案例配套的 NC 程序仍待确认。[传动轴教学案例候选](https://bharatskills.gov.in/pdf/E_Books/CTS/37/English/TT/Machinist%20-%202nd%20Year%20-%20TT%20%282022%29.pdf) · [三菱 B196C 中文手册](https://data.mmc-carbide.com/7516/9535/1479/b196c_mc60.pdf)
