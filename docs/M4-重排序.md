2026-11-21，沿用 M3 的 107 个条目、6 道开发题。每题只执行一次双路召回，从 RRF 排在前面的 20 个唯一条目中，比较直接截取前 5 与硅基流动 BAAI/bge-reranker-v2-m3 精排后取前 5。模型联合读取问题与各候选的来源、PDF 页码和正文。输出保留条目 ID、原始名次、精排分数和页表定位。

|---|---:|---:|---|
| M1-01 指定刀片进给 | 5 | 5 | 目标行在两种模式均第 1 |
| M1-02 仅知 MC6025 | 2 | 5 | 原首条为量具表。精排后首条来自原第 16 名，五条证据展示不同条件，应据此追问 |

完整标注页覆盖为 6/6 → 6/6。前 5 中来自标注页的比例为 16/30 → 21/30。页内的其他参数行也会计入这一指标，因此另查 M1-01 的精确行名次；工艺答案质量仍需人工评分。该分数用于候选排序，不能直接当作拒答概率。

## 复现与接口

在仓库根目录运行：

```bash
.venv/bin/python search.py '只有 MC6025 能确定每转进给量吗？' --mode rerank -k 5
.venv/bin/python eval_retrieval.py --m4
.venv/bin/python -m unittest discover -s tests
```

逐题明细在 output/M4/api/development-results.json。--mode ablation 可在同一候选池同时返回基线与精排。接口失败会显式报错，避免把未精排结果计入实验。可选 --backend local 通过 FlagEmbedding 的 FlagReranker 在 CPU 上运行，需要另行安装 FlagEmbedding 并准备模型权重。本次实测为 API 模式；本地模型的效果、内存与耗时待独立验证。切换本地重排时，稠密查询仍沿用 M2 的向量 API。
