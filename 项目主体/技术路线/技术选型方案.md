# 基于 RAG 的轻量级企业工艺生成系统 · 技术选型方案

## 一、技术选型总览

| 层 | 推荐选型 | 备选 | 选型理由 |
|---|---|---|---|
| 编程语言 | Python 3.10+ | — | 生态全，有基础 |
| RAG 框架 | LangChain | LlamaIndex、纯手写 | 资料多、组件全、好排查 |
| PDF 解析 | PyMuPDF（主）+ pdfplumber（表格） | MinerU（扫描件） | 快，表格能力强 |
| 分块 | LangChain RecursiveSplitter（表格保护） | 语义分块 | 最常用，表格特殊处理 |
| Embedding | BGE-M3（智源开源） | bge-large-zh-v1.5 | 稠密+稀疏一体，中文强，8192长文本 |
| 向量数据库 | Chroma | FAISS、Qdrant | 选题指定，pip即用，零运维，本地持久化 |
| BM25 | rank_bm25（纯Python） | Elasticsearch | 轻量，无需部署 |
| 重排序 | bge-reranker-v2-m3（智源） | Cohere Rerank | 开源、中文强、568M轻量 |
| 结果融合 | RRF（自写） | 加权融合 | 简单鲁棒，工业界标配 |
| 大模型 API | DeepSeek（deepseek-chat） | 通义千问、GPT-4o-mini、Claude Haiku | 国内直连、便宜、中文强、兼容OpenAI |
| 对话界面 | Gradio | Streamlit、FastAPI | 几行代码出对话界面 |
| 项目管理 | Git + GitHub/Gitee | — | 老师要求 |

## 二、选型理由

### 1. 向量数据库：Chroma
- Chroma：pip 装即用，数据存本地，零部署零运维，契合"轻量级"
- Weaviate：需 Docker 部署，偏生产，学习项目偏重

### 2. Embedding：BGE-M3
- 智源（BAAI）开源，一个模型同时支持稠密+稀疏+多向量检索
- 支持100+语言，中文强，最长8192 token
- 完全开源免费

### 3. 重排序：bge-reranker-v2-m3
- 568M 参数，约 2.27GB，轻量 Cross-encoder
- 中文 C-MTEB 成绩优秀
- 可本地 CPU/MPS 跑或 API，FlagEmbedding 调用简单

### 4. 大模型 API：DeepSeek
- 国内直连无需代理，中文强，兼容 OpenAI 接口
- 价格极低（输入约2元/百万token，输出8元）
- 通义千问（稳定、免费额度）、GPT-4o-mini/Claude（需海外网络）为备选

### 5. PDF 解析：PyMuPDF + pdfplumber
- PyMuPDF（fitz）：极快，提取文字/图片/页码/坐标，新版表格准确率高
- pdfplumber：单元格级表格结构，适合切削参数表
- 扫描件再引入 MinerU / OCR

### 6. 框架策略
- LangChain 做胶水：加载、分块、模型调用、接口封装
- 混合召回、RRF融合、重排序核心链路自己写（约几十行）
  - 原因：这是项目核心技术点，避免黑盒，便于答辩和报告

## 三、模型运行方式

### 方案 A：全 API（推荐入门）
- Embedding/Reranker：硅基流动 SiliconFlow API（免费提供 BGE-M3、bge-reranker）
- 大模型：DeepSeek API
- 优点：环境快、不占内存；缺点：需联网

### 方案 B：本地模型（更开源）
- Embedding/Reranker：FlagEmbedding 本地跑（Mac CPU/MPS 可行）
- 大模型仍用 API
- 优点：免费离线、报告好写；缺点：下载数GB、CPU稍慢

建议：先用方案A跑通全流程，再切方案B做"本地 vs API"对比实验。

## 四、对应5个要求

| 要求 | 实现 |
|---|---|
| ① 文档格式解析 | PyMuPDF + pdfplumber（文字、表格、页码、图片） |
| ② 稠密+稀疏混合召回 | BGE-M3稠密 + Chroma；rank_bm25稀疏；RRF融合 |
| ③ 重排序 | bge-reranker-v2-m3 Cross-encoder |
| ④ 多轮对话与引用溯源 | 历史管理+查询改写；metadata带页码+引用编号+Gradio |
| ⑤ 多文档测试准确率 | 多份文档+人工评估表+对比实验（有无混合/重排序） |
